# Semifly 上游运营后台：分阶段实施设计

状态：设计基线，尚未实现；2026-09-23。不得据此宣称已支持自动准入、自动故障转移或成本对账。

## 现状核查

- `gateway/upstreams.py` 从配置读取上游，凭据引用环境变量；一个公开模型对应一个 Route，没有多通道池。`weight` 是旧版点数扣费倍率，不是路由权重。
- `gateway/app.py` 的 `/admin/status` 只检查上游 `/models` 是否返回 200，不能证明具体型号可调用、真实身份或容量。
- 代理已有调用用量与耗时记录、账户模型额度预留和结算；没有完整的多次尝试链路及供应商成本账本。
- 现有管理口令入口和账户 system_admin 入口并存。新管理能力采用服务端管理员角色校验，不通过公开静态页面或用户名判权；敏感发布要求二次验证。不能把现有管理员登录等同于已实现 MFA。

## 三个中心与职责边界

1. 上游准入中心产出：已批准的模型通道、验证证据、能力约束。批准不等于发布。
2. 模型路由中心消费合格通道，产出版本化路由配置；负责主备、熔断、恢复及发布回滚。
3. 请求与成本账本关联客户请求和每次上游尝试，分别记录客户结算及上游成本，不能将未知费用记为零。

三者共享 provider_id、credential_id、channel_id、public_model_id；请求阶段增加 request_id、attempt_id 和 route_revision。凭据更新不能破坏历史引用。

## 第一步：上游准入中心

### 页面与操作

主页面采用紧凑表格：供应商、通道型号、来源审核、能力检测、最近检测、状态、操作。支持供应商/状态/型号筛选、搜索与分页。

顶部显示待审、检测中、待批准、隔离数量；批量导入先预览并逐行展示错误，不自动发起付费测试。详情用侧栏展示：基本资料、来源证据、型号能力、检测报告、操作历史。

流程：导入草稿 → 审查来源 → 设置测试预算并运行 → 查看报告 → 管理员批准。失败或证据不足保持隔离，不进入生产路由。撤销批准立即使其失去发布资格，运行中路由的退出由后续发布机制处理。

### 数据实体

| 实体 | 关键字段 |
|---|---|
| provider | 名称、协议适配器、来源类型、证据引用、数据政策、账户故障组 |
| credential | provider_id、secret_ref、掩码、版本、状态；不返回明文 |
| channel | provider_id、credential_id、base_url、声称型号、核验版本、已测能力、地域、限流故障组、审核状态 |
| probe_run | channel_id、配置版本、测试集版本、预算、开始结束时间、整体结论 |
| probe_result | run_id、测试项、通过/失败/不支持/未知、耗时、usage 来源、费用来源、脱敏证据 |
| review_event | 操作者、动作、对象、前后版本、原因、时间；追加而非覆盖 |

来源审核、检测运行和准入状态分开存储；测试通过不得自动将来源改成可信。审批绑定精确配置与检测版本；端点、凭据、型号或关键能力变化后重新验证，不继承旧批准。

### 导入契约

首版 CSV/JSON 元数据：supplier_name、base_url、protocol、credential_ref、claimed_model、region、account_group、evidence_ref。一个上游多个模型展开为多条通道；目录发现结果仅作为候选。

导入文件不放明文 Key。凭据通过单独受保护入口保存，导入只引用 secret_ref。重复导入幂等；有冲突生成待审变更，不覆盖已批准配置。对文件大小、行数、字段长度和协议设置白名单。

### 测试范围与边界

首版仅 OpenAI 兼容文本接口：目录发现（可不支持）、小额非流式生成、流式正常结束、usage 字段合法性与耗时。工具/结构化输出等能力逐项扩展，未经测试不标支持。

所有请求使用合成内容，无真实客户对话。每轮有请求数、输出 token、并发、时长和费用预算；未知价格不自动运行计费测试，先提供人工确认的保守成本上界。测试预算不承诺供应商不超报，账单仍需后续对账。

每个结果标注样本量、测试版本、时间；初筛少量样本不用于宣称稳定性 SLA。模型身份只记录证据等级，不输出“黑盒百分之百验真”。余额无法查询显示未知。

安全要求：验证 HTTPS、TLS 和所有解析地址；禁止自动重定向，阻止环回/私网/链路本地/云元数据及 DNS 重绑定；受信任自建内网节点使用单独运维白名单，不对批量导入开放。凭据只发送到核准端点，错误正文脱敏并限长。检测在有出站约束的任务进程运行，不阻塞客户请求。

### 首版验收

- 重复导入不重复建档；错误行报告可定位，批准配置不被覆盖。
- 普通客户和未登录请求不能读取、修改或运行检测；日志、导出及响应不含密钥。
- 内网地址、重定向及解析地址改变的测试被拦截。
- 假目录、401、429、超时、坏 JSON、断流、缺失或非法 usage 分别产生明确报告。
- 达预算/时间/请求上限停止任务；未批准通道不能成为生产候选。
- 批准/撤销均留审计；配置变化使旧检测和审批失效。
- 全部先用本地模拟供应商验收，无真实上游费用，不修改线上路由和现有计费。

## 后续里程碑

第二步：先提供只读路由视图，再以同模型双通道实现有界重试、共同故障组识别、熔断和恢复；开始向客户发送流式内容后不得拼接替代答案。不同型号不得默认替换。

第三步：在任何生产重试上线之前，实现 request/attempt 关联和幂等结算；成本使用独立精度金额、币种、费率版本和已报/估算/未知状态；记录失败尝试成本，保留对账调整。第三步的数据基础必须与第二步联调，不能先上重试再补账。

正式发布需灰度、回滚方案和故障演练。当前文档阶段不部署、不收费、不调用外部供应商。
